# v0.3.6 实施方案

## 1. 已验证结论

- prompt 文本能稳定控制比例：`9:16 -> 720x1280`、`16:9 -> 1280x720`、`1:1 -> 720x720`。
- prompt 文本不能控制时长；豆包结构化默认值 `自动 · 10s` 生成约 `10.080s` 成片。
- 参数后缀没有造成画面文字污染。
- v0.3.6 产品规则：新创建、手动重新生成和 queued 待提交任务统一为 10 秒；创建层仅支持 t2v。

## 2. 固定 10 秒不变量

### 协议

`src/doupool/video/protocol.py` 新增：

```python
FIXED_VIDEO_DURATION_SECONDS = 10
```

旧 `DURATIONS`、i2v payload 和 UI 参数 helper 保留，供未来恢复可变时长和旧 fetch 路径回滚。

### Settings

- `default_duration` 默认值为 10。
- `get()` 忽略旧 SQLite 行中的非 10 值，但不删除或迁移该行。
- `update()` 在校验前把任何 `default_duration` 输入规整为 10。
- 内部 `_validate()` 只接受最终值 10。

### API

- `CreateVideoTaskBody.duration` 默认 10。
- Pydantic `field_validator(mode="before")` 把任何显式 duration 输入规整为 10。
- 路由在 `model_dump()` 后再次写入 10。
- schema 用真实字段 `images` 拒绝 `mode != "t2v"` 或非空图片附件。

### Service

- `VideoTaskService.start()` 在校验、计费和落库前把 duration 规整为 10。
- model、ratio 和 duration 协议校验继续保留。
- service 再次拒绝 `mode != "t2v"` 或非空 `images`。
- `quota_cost(model, 10)` 决定预扣：Mini 10 点，Fast/Std 15 点。

### 两类 retry

- 前端“重新生成”通过创建端点再次进入 `start()`，因此新任务按 10 秒落库和计费，并继承原 `group_id`。
- `/api/requests/{id}/retry-result` 只重解析已有会话，不生成、不预扣、不计费，也不规整历史 duration。
- 历史 i2v 的重新生成被创建层拒绝；历史 i2v 的 `retry-result` 继续放行。

### queued 启动恢复

启动顺序固定为：

1. 识别并清理 stale queued；assigned stale 先退款再解绑。
2. 扫描 `status=queued AND duration!=10`。
3. assigned 任务在数据库事务中退旧预扣、解绑、写入 10，并尝试按新成本重新 CAS 预扣。
4. 新成本无法容纳时保持 unassigned queued，不允许额度桶越上限。
5. 重建 `_pre_charged_tasks` 后才放行 worker。

未绑定 queued 任务由 worker 使用 `choose_and_reserve_account(..., by=quota_cost(model, 10))` 原子选择和预扣，禁止旧的“只检查 used < limit 后直接加成本”路径。

## 3. 浏览器提交新入口

主流程：

```text
外层 Aegis gate
  -> 左侧“新对话”
  -> 输入框工具条“更多”
  -> “视频生成”
  -> placeholder/chip/model 三重断言
  -> task 级模型显式选择
  -> data-selected=true + 模型按钮文本双回读
  -> 第一层内部 Aegis gate
  -> clear_prose_mirror
  -> clipboard writeText + Ctrl+V
  -> 第二层内部 Aegis gate
  -> #flow-end-msg-send
  -> ACK
  -> 现有 polling/recheck
```

灰度账号兼容：连续两次打开“更多”后若菜单确实没有“视频生成”，记录
`video_generation_legacy_tab_fallback`，导航到 `/chat/create-image`，只做最小
视频 TAB 激活，再以可见编辑器和视频模型按钮确认就绪。该兜底不打开参数菜单、
不调用 `_apply_video_options`；比例仍只由 prompt 文本控制，时长仍由“自动 · 10s”接管。

稳定选择器：

| 目标 | 选择器 |
| --- | --- |
| 新对话 | `div[class*="group/sidebar_nav_item"]` + exact text |
| 更多 | `button.skill-bar-button` + exact text |
| 视频生成 | `button[data-component-type="skill-item"][data-skill-id="skill_bar_button_17"]` |
| 编辑器 | `[contenteditable="true"][role="textbox"]` |
| placeholder | `[data-placeholder="描述你想要的视频"]` |
| chip | `[data-input-engine-action-source="actionbar"][data-value="17"]` |
| 模型按钮 | `button[data-input-engine-actionbar-control-key="video-model"]` |
| 发送 | `#flow-end-msg-send` |

模型映射：

```python
{
    "seedance_v2.0_mini": "Seedance 2.0 Mini",
    "seedance_v2.0_std": "Seedance 2.0 Fast",
    "seedance_v2.0": "Seedance 2.0",
}
```

prompt 每次都从原始文本重建：

```python
base = prompt.rstrip()
sep = "" if base.endswith(("。", "！", "？", ".", "!", "?")) else "。"
submitted = f"{base}{sep}时长{duration}秒，比例{ratio}"
```

其中比例文本已验证生效；时长文本仅保持语义完整，实际 10 秒由豆包结构化默认值接管。

旧 `_click_video_tab`、`_apply_video_options`、`_open_video_options`、`_set_aria_slider_value` 及其严格 readback 全部保留定义，生产路径停止调用。灰度兜底使用独立的 `_activate_legacy_video_tab`，避免重新依赖已停用的参数菜单。

## 4. ACK 四态

拦截器同时记录 `/chat/completion` request 和 response：

| 状态 | 行为 |
| --- | --- |
| 有效 ACK | 只提交一次，进入 polling |
| Aegis | fail-fast、释放 profile、失败退款，不自动重发 |
| ACK 超时且 `request_seen=false` | 完整新会话流程最多重试一次 |
| ACK 超时且 `request_seen=true` | 歧义状态，禁止自动重发 |

重试始终从原始 prompt 重建后缀，不能重复追加。

## 5. 前端

- 新建与手动重新生成 payload 显式发送 `duration: 10`、`mode: "t2v"`、`images: []`。
- 时长控件固定显示禁用的 10 秒；settings 加载旧值后和保存前都强制为 10。
- 移除图片上传、预览和自动切换 i2v 的创建 UI。
- 历史 i2v 任务继续展示，但隐藏其“重新生成”按钮。
- 下载失败后的 URL 刷新和后端 `retry-result` 保持 mode 无关。

## 7. 回滚保留

固定 10 秒和 t2v-only 是当前产品约束，不是永久删除底层能力。旧结构化参数 UI、fetch payload、i2v browser 分支及协议定义继续保留，未来恢复前需重新做真机验证。
