### Phase-3: P1 Optional Hardening

**Requires `.pyd` rebuild** (P1-A/P1-B modify `verifier.pyx`)

**P1-A: Clock Rollback Defense** (`src/doupool/license/verifier.pyx:199`)
```python
# Detect server timestamp rollback (defense against local clock tampering)
if last_server_sync > 0 and server_timestamp < last_server_sync:
    return "clock_rollback"
```
- `last_server_sync`: previous successful heartbeat's server timestamp (stored in activated.bin)
- `server_timestamp`: current heartbeat's server timestamp
- Monotonicity requirement: `server_timestamp >= last_server_sync`
- Violation → `clock_rollback` status → gate rejects startup

**P1-B: fresh_until<=0 Never-Expire Hole** (`verifier.pyx:218-221`)
```python
# Before: fresh_until=0 bypassed grace period check (7-day window forever valid)
# After: fresh_until<=0 must complete first heartbeat within 7-day grace period
if fresh_until <= 0 or (current_time - fresh_until) > _GRACE_PERIOD_SEC:
    return "expired"
return "grace_period"
```
- Closes "activate once, never connect again" offline abuse path

**P1-C: Response client_pubkey Echo Verification** (`heartbeat.py:194-199`)
```python
# Server echoes client_pubkey in response; client must verify it matches request
response_pubkey = response.get("client_pubkey", "").lower()
if not response_pubkey:
    logger.error("响应缺失 client_pubkey 字段")
    return False, ErrCode.BAD_RESPONSE
if response_pubkey != expected_client_pubkey_hex:
    logger.error("响应 client_pubkey 不匹配: expected=%s, got=%s",
                 expected_client_pubkey_hex, response_pubkey)
    return False, ErrCode.BAD_RESPONSE
```
- Defense-in-depth: server signature already covers `client_pubkey` (Phase-2 V4 verified), this adds explicit client-side echo check
